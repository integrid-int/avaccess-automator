# AVAccess Route Planner Track B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute Track A `RoutePlan` objects live (IR tune + UDP reconnect) with a hybrid dry-run/live toggle, using a striped inventory and adapters from the preset-plan engine.

**Architecture:** Keep JS `buildRoutePlan` as the planner. Add a Python executor that validates inventory, enriches each slot with TX/RX hostnames, then for each slot runs iTach IR digits followed by UDP `msg_b_reconnect`. The bartender panel gains a Live commit toggle gated on inventory validation; Live Send posts the plan to HA `shell_command` (base64 JSON). Default remains dry-run.

**Tech Stack:** Python 3.12+, PyYAML, existing UDP/iTach script patterns from `origin/cursor/avaccess-preset-plan`, Home Assistant `shell_command` + `input_boolean`, Node tests for panel contracts, pytest for Python.

- Spec: `docs/superpowers/specs/2026-08-10-avaccess-route-planner-design.md` (Track B)

### Task 3: Execute RoutePlan (IR then UDP)

**Files:**
- Create: `config/itach.example.yaml` (copy from preset-plan; keep REPLACE placeholders for codes OK)
- Create: `scripts/avaccess/udp_reconnect.py`
- Create: `scripts/avaccess/ir_itach.py`

- Create: `tests/test_execute_route_plan.py`

**Interfaces:**
- Consumes: enriched plan, inventory, itach config
- Produces CLI:

```bash
python3 scripts/avaccess/execute_route_plan.py \
  --inventory config/inventory.yaml \
  --itach-config config/itach.yaml \
  --plan-file /tmp/plan.json \
  --dry-run
# or
  --plan-b64 '<base64>' \
  --live
```

Behavior:
1. Load plan JSON; `enrich_route_plan` if any `udp` is null
2. If `--live`: require `validate_inventory_for_plan` OK; else exit 2
3. For each slot in order:
   - If `tune.channelNumber`: send IR digits + `ok` via iTach (`digit-delay-ms` default **250**)
   - Build `msg_b_reconnect {tx}:{session}:{n} {rx...}`; session increments per slot
   - Send UDP broadcast (or print in dry-run)
   - Set `slot.status` to `ok` or `error` with message; **continue** after errors
4. Print final JSON report to stdout: `{ "ok": bool, "slots": [...], "errors": [...] }`
5. Exit 0 if all slots ok; exit 1 if any slot error; exit 2 if preflight fail

Reuse protocol helpers adapted from preset-plan `route_targets.py` / `send_xumo_ir_itach.py` (factor into `udp_reconnect.py` / `ir_itach.py`).
